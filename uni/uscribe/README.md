# uscribe

A prose/book doc generator for Unicon. Lives as a top-level sibling of
`uni/unidoc/`, not nested inside it: unlike the legacy `parlett/`
implementation (an archived, superseded variant preserved inside
`uni/unidoc/`), `uscribe` is an independent, actively developed tool
with a different scope (prose/book vs. source-comment API extraction)
and deliberately does not touch `unidoc`'s internals. Location:
`uni/uscribe/` in the unicon tree.

**Status: builds and runs end-to-end.** Organized as a real Unicon
package (`package uscribe`, mirroring `package UniDoc` in
`UniAll.icn`/`UniForm.icn`/`UniHTML.icn`) with real per-file build
dependencies generated by `unidep` (see "Build" below — this required
a small `unidep`/`uni/parser` fix, cherry-picked from
`uniconproject/unicon` commit `d9926fd`). Compiled and linked via its
actual `Makefile` inside a real clone of `github.com/uniconproject/unicon`
(installs to `../../bin/uscribe`, same as `unidoc`), and verified on
the sample book in `example/` — headings/nesting,
`*emphasis*`/`**strong**`/`` `literal` `` inline markup, bullet lists
with wrapped continuation lines, `.. note::` admonitions with body
text, `.. code-block::`, and a resolved cross-chapter `` :ref:`` ``
link all produce well-formed HTML. See "Try it" below.

## Package structure

`uscribe`'s library files (everything except `main.icn`) declare
`package uscribe`, mirroring how `UniAll.icn`/`UniForm.icn`/
`UniHTML.icn` all declare `package UniDoc`. Files within the package
reference each other's classes directly with no cross-file import
needed — only `main.icn`, which stays in the default/unnamed package
(matching `UniDoc.icn`'s own role as the driver), does `import
uscribe` to reach in.

This surfaced a real, easy-to-hit build-ordering trap: `main.icn`
must be *compiled* after the package files it imports from, or
`import uscribe` resolves to nothing and every package symbol it
uses (e.g. `DirectiveRegistry`, `Manifest`) fails at runtime with
misleading errors. `make`'s default wildcard-discovered file list
compiles alphabetically, which put `main.icn` first — broken. Fixed
by generating real per-file dependencies with `unidep` (see "Build"),
matching how `unidoc/Makefile` gets its own autogenerated dependency
footer.

## Why separate from unidoc

`uni/unidoc/UniAll.icn` parses Unicon *source* to find packages,
classes, methods, and globals. `UniHTML.icn`'s `cmts2html()` then
turns comment text (which already contains embedded HTML tags) almost
verbatim into an HTML string. There's no renderer-independent doctree
and no concept of chapter ordering across files — both are out of
scope for what it does well (API extraction), so this is a new parser
and a new doctree rather than a patch to `UniAll`.

The legacy `uni/unidoc/parlett/` version (preserved, superseded) has
the better shape to imitate: `Comment`/`Class`/`Method`/`Package` model
classes are separate from `HtmlOutputter`/`GroffOutputter` renderer
classes. `uscribe` follows that split, just with a real doctree
(`node.icn`) instead of Comment's raw-line/`@field` storage.

## Layout

| File            | Role |
|-----------------|------|
| `node.icn`       | Doctree: `Document, Section, Paragraph, BulletList, EnumList, ListItem, CodeBlock, Admonition, TableNode, ImageNode, RawDirective` (block) + `Text, Emphasis, Strong, Literal, Reference, PendingXref` (inline), plus a `nodeType()` discriminator on every concrete class and safe `mk*()` factory procs. |
| `scan.icn`       | Generalized version of `UniHTML.icn`'s `checkSpecial()`/`parseClause()` balanced-tag scan, decoupled from HTML output and from UniDoc's specific field names. Not yet wired into `parser.icn` (see Open work). |
| `inline.icn`     | `parseInline(s)`: `*emph*`, `**strong**`, `` `literal` ``, `` :ref:`label` ``, `` :doc:`file` `` → list of inline nodes. |
| `outputter.icn`  | Abstract `Outputter` (one `visitXxx` per node type) + concrete `HtmlOutputter`. Modeled on `parlett/htmloutputter.icn` + `groffoutputter.icn`'s split, not on `UniHTML.icn`. |
| `manifest.icn`   | `Manifest`: ordered chapter list (the toctree equivalent), loaded from a flat manifest file. |
| `labeltable.icn` | `LabelTable`: two-pass cross-ref resolution — `collect()` over every chapter, then `resolve()` swaps each `PendingXref` for a `Reference`, keyed off each `Section`'s `nodeType()`/slugified title. |
| `directive.icn`  | `DirectiveRegistry`: name → handler. Ships `code-block`/`note`/`warning`/`tip`/`image`; commented-out sketch of an `.. api::` handler that would bridge to UniDoc. |
| `parser.icn`     | Line-oriented parser: underline headings, blank-line paragraphs, `-`/`*` bullet lists, `.. name:: arg` directives with indented bodies. |
| `main.icn`       | Driver: parse every chapter (pass 1) → collect labels → resolve + render every chapter (pass 2). |
| `Makefile`       | Build, mirroring the current `uni/unidoc/Makefile` pattern (wildcard-discovered `.icn` sources, direct multi-file link, autogenerated dependency footer via `unidep`) — not the legacy `parlett/Makefile`, whose separate `linkfiles.icn` indirection was a workaround for command-line-length limits that the current tooling doesn't need. |
| `example/`       | Working two-chapter sample book (`book.idx`, `intro.rst`, `chapter2.rst`) exercising every feature currently implemented. |

## Try it

Requires a built `unicon` toolchain (`./configure && make` from a
clone of `uniconproject/unicon`) that includes commit `d9926fd`
("uni: Resolve unidep/parser library paths via IPL paths helpers") —
without it, `unidep` can't resolve the `lang`/`util` package paths
`uscribe`'s files import, and `make deps` fails with "unknown
package lang/util". If your checkout predates that commit, cherry-pick
it (`git cherry-pick d9926fd11859edd91e753da22b48bfe26205adea`) and
rebuild `uni/parser` and `uni/unidep` before building `uscribe`.

```sh
cd uni/uscribe
make

# produces ./uscribe and installs a copy to ../../bin/uscribe

cd example
../uscribe --manifest=book.idx --title="Test Book" --targetDir=./out
# writes ./out/intro.html and ./out/chapter2.html
```

## Real Unicon-specific bugs found while getting this to build/run

Worth keeping in mind for anyone extending this (or writing new
Unicon OOP code generally) — none of these are exotic, but each one
produced a plausible-looking silent failure rather than an obvious
error:

- `Object` and `Args` come from `import lang` / `import util`
  respectively, not built in. Every file that declares a class needs
  `import lang`; `main.icn` additionally needs `import util`.
- **Procedures and methods both fail by default if control falls off
  the end of the body without an explicit `return` or `fail`** — this
  is a single uniform rule, not a methods-vs-procedures distinction (an
  earlier version of this note wrongly framed it as method-specific).
  A routine can run every side effect correctly and still report
  failure to a caller using `|` for error handling, simply because the
  last statement executed wasn't a `return`. This silently broke ~70
  methods here; fixed by auditing every routine for a terminal
  `return`.
- Procedure names are global across a whole linked program, not
  file-scoped — two files each defining `procedure slugify(s)`
  produced a link-time "inconsistent redeclaration" error, not a
  per-file shadowing.
- `&subject[i:j]` (slicing the scan-environment keyword directly)
  returns a lazy value tied to the *outer* scan's position tracking.
  Using it as the source of a *new* `s ? {...}` scan corrupts position
  bookkeeping and crashes with "invalid value." Force a real copy with
  `"" || &subject[i:j]` before reusing it as a scan subject.
- There is no niladic `pos()` to fetch the current scan position —
  that's the `&pos` keyword. `pos(i)` is a one-argument *test*
  function; calling it with zero arguments silently passes `&null` as
  the argument (functions fill missing trailing args with `&null`
  rather than erroring at the call site) and then fails deep inside
  with a confusing "integer expected, offending value: &null".
- Referencing a method an object's class doesn't define (e.g. calling
  `.getLevel()` on a `Paragraph` node while duck-type-checking for
  `Section`) is a hard runtime error ("invalid field name"), not a
  graceful failure — there's no safe `respondsTo?`-style check.
  Needed an explicit `nodeType()` discriminator method instead.
- `expr1 & expr2` fails if `expr1` fails; if `expr1` succeeds, it
  evaluates and returns the result of `expr2` — `expr1`'s own result
  (as opposed to its success/failure) is discarded. It is not a
  boolean-AND with an implicit truthiness check on numeric/string
  values. `many(' ') & 1 to n` doesn't mean "cap the match at n
  characters"; `many(' ')` only gates whether evaluation proceeds,
  and the expression's actual value comes from `1 to n`, so it
  silently evaluates to `1` (that generator's first result) rather
  than any bounded match length. Bounded matching needs an explicit
  counted loop instead.
- `any(cset)` only *tests* the character at the current position; it
  never advances `&pos`. Following it immediately with another match
  (e.g. `=" "`) tests the *same* position twice. Use `tab(any(cset))`
  to actually consume the matched character.
- `pop(list)` removes from the **front**; the back-removal primitive
  is `pull(list)`. A "trim trailing blanks" loop written with `pop()`
  silently trims from the wrong end.
- `many(cset)` requires **at least one** match and fails on zero —
  useful for "must be indented" checks, but a bug magnet for "optional
  leading whitespace" checks (bullet markers, arbitrary indentation)
  where zero is a valid case. Needs an explicit `| &pos` (no-op)
  fallback wherever zero should be allowed.
- A file that does `import somePackage` must be **compiled after**
  every file that declares `package somePackage` — `import` resolves
  against a per-directory class database (`uniclass.dir`/`.pag`)
  populated by compiling the package's own files first, not against
  source at compile time. A wildcard-ordered (alphabetical) build list
  can easily put the importing file first, silently breaking every
  symbol it pulls from the package. `unidep` generates the correct
  per-file dependency rules to prevent this — see "Try it" for a
  related `unidep` bug this surfaced (unresolvable `lang`/`util`
  package paths without a specific upstream fix).

## Open work

- `scan.icn`'s generalized balanced-directive scanner isn't wired into
  `parser.icn` yet — directive parsing currently uses simpler
  `find("::")`-based scanning, which is adequate for the directives
  implemented so far but won't handle directives needing nested
  balanced delimiters.
- The RST subset is intentionally small: no tables or definition
  lists yet (`TableNode` exists in the doctree but nothing produces
  one). Extend `parser.icn` as real chapters expose gaps.
- `stripIndent`'s body-indent amount is a hardcoded minimum (4), not
  measured from the directive body's actual first line — works for
  the example book but should be measured properly for arbitrary
  indentation depths.
- `HtmlOutputter` emits one flat page per chapter — no frameset/nav
  chrome yet (see the refactor items below).

## Refactors this depends on, back in classic UniDoc

Not done here (would touch `uni/unidoc/` itself, which this tool
deliberately avoids modifying) but needed before the `.. api::` bridge
in `directive.icn` can be un-commented:

1. Expose `UniAll.processFile()` + `UniHTML.buildPages()` as an
   in-process callable returning a page manifest, instead of the only
   entry point being the compiled `unidoc` binary's CLI.
2. Extract `UniHTML.icn`'s page-shell code (`pageTop`, `pageBottom`,
   `navFrameRef`, `openStdHtmlFile`, `makeDirPath`) into a standalone
   module with no dependency on `UniAll`'s entity tree, so `uscribe`'s
   `HtmlOutputter` can share the same frame/nav chrome instead of
   growing its own.
